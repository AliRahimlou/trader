# Version 4.3.0 — shared entry allowance and execution verification

The two live-capable engines previously shared available capital but did not enforce the approved maximum of two new entries per New York session. Both now reserve an entry attempt in the same SQLite transaction that claims the durable submission operation. The cap spans both engines and processes; restarts, permission toggles, rejected or uncertain outcomes, and completed trades cannot refund an attempt. Existing attempted entries are conservatively backfilled. Unusable legacy evidence blocks new entries while preserving position management.

This is a conservative submission-attempt allowance, not a filled-trade counter. An operation claimed before a subsequent pre-submit failure still counts. Claims within ten seconds of New York midnight reserve both adjacent session dates, covering the bounded handoff to the broker. Stop and exit operations never consume entry allowance. The dashboard distinguishes saved permission, available allowance, submission attempts and confirmed fills; its initial controls wait for saved state before displaying On or Off.

Stock order reconciliation now checks returned broker evidence against its retained intent, including quantity or notional, prices, order scope, time in force, identifier and nondecreasing finite fills. It accommodates documented stop conversions and fractional notional responses. Inconsistent evidence retains the last verified lifecycle state and blocks new entries while reconciliation continues; it does not resubmit an uncertain order.

The updater retains a session-entry capability marker in future maintenance holds. A release or rollback that cannot acknowledge that marker cannot reopen entries. Do not roll back to an unguarded build by deleting its hold. Use a corrective release retaining the cap and persistent data. The initial upgrade is necessarily started by the previously installed updater; the marker protects subsequent guarded deployments.

Five pinned Python dependencies were updated to compatible fixed releases after an advisory scan. The disconnected research simulator now counts submission attempts consistently, preserves caller ordering for simultaneous candidates, and censors missing price coverage rather than reporting unsupported confidence intervals. No research candidate, new strategy rule, leverage, sizing increase or permission change is activated by this release.

Required verification includes isolated Python and browser-model tests, frontend compilation, and the Docker release build. Fixtures exercise broker failures and full trade lifecycles without financial network access. A successful build or broker read does not establish a live fill or a profitable strategy. The strategy's unresolved source parameters, gap risk, stop-limit non-fill risk, and absent owner-defined portfolio loss budgets remain limitations.
